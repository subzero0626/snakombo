5. Key events: client sends input to host
   Lines: 1621-1668 (keydown/keyup handlers)
------------------------------------------------------------
In the keydown handler (line 1621), wrap the key assignments with:

  if (typeof onlineRole !== 'undefined' && onlineRole === 'client') {
    // Don't set local keys; send to host instead
    if (typeof onlineSendInput === 'function') {
      onlineSendInput({ key: e.key, type: 'down' });
    }
    return;
  }

Similarly in keyup (line 1662):

  if (typeof onlineRole !== 'undefined' && onlineRole === 'client') {
    if (typeof onlineSendInput === 'function') {
      onlineSendInput({ key: e.key, type: 'up' });
    }

  }

The host's online.js should listen for these input messages and
apply them to the player 2 keys (keys.left / keys.right), since
the client controls player 2 in the local multi framework.

6. Game start: wait for both connected, host signals start
   Line: 3403 (function startGame())
------------------------------------------------------------
When online mode is active:
  - Do NOT call startGame() directly from the online panel
  - Instead, when both peers are connected (#online-connected shown),
    the host waits ~1.5s then sends a "start" signal
  - Both host and client call startGame() upon receiving/sending
    the start signal
  - Before calling startGame(), set:
      gameMode = 'multi';
      nextRunIsLocal = true;   // reuse local 2P framework
      localPlayEnabled = true;

  The online.js module should export/expose a function like:
    onlineStartGame() {
      nextRunIsLocal = true;
      localPlayEnabled = true;
      startGame();
    }

  For the host: call onlineStartGame() and send 'start' message.
  For the client: on receiving 'start' message, call onlineStartGame().

Additional notes
------------------------------------------------------------

- The menuStartStage system (line 3467) currently supports
  'start' | 'choose'. The CSS already handles 'online_panel'
  stage (main.css lines 207-218, 340-344). Extend the JS
  comment and setMenuStartStage to accept it.

- The menu-start-row transition system (lines 3495-3539)
  supports t1-forward, t1-back, t2-forward, t2-back, t0-back.
  The CSS for t2 transitions (choose <-> online) exists at
  main.css lines 249-266. Add a new transition for
  choose -> online_panel if desired, or reuse t2-forward.

- online.js should be a self-contained module that:
  - Exposes: onlineCreateRoom, onlineJoinRoom, onlineCancelHost,
    onlineCancelJoin, onlineCloseAll, onlineSendState,
    onlineGetLatestState, onlineSendInput
  - Manages: PeerJS peer lifecycle, data channel, room codes
  - Updates: DOM elements (#online-lobby, #online-host-waiting, etc.)
  - Sets: window.onlineRole = 'host' | 'client' | null

- The existing local multiplayer (localPlayEnabled) framework
  handles two snakes with separate controls (A/D vs Left/Right).
  Online mode should reuse this by having the host run physics
  for both snakes, with the client's inputs mapped to player 2.
